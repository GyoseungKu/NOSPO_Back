# 회원 탈퇴 구현 — 1단계

이번 정책은 기능 명세 v2.1과 개발 규칙의 즉시 삭제·복구 불가 정책을 대체합니다. 즉시 접근을 차단하고 개인정보를 30일 암호화 보관하며, 기한 내 복구 시 기존 회원 ID·로그인 수단·지갑·잔액·가입 보상 원장을 유지합니다. 복구 보상은 지급하지 않습니다. 정확히 30일에 도달하면 복구 불가이며, 개인정보 삭제 후 신규 가입에는 기존 보상 정책을 적용합니다.

**현재 구현은 탈퇴·암호화 보관·접근 차단까지입니다. 복구 API와 기한 후 삭제 워커는 없습니다.** 만료 인덱스도 아직 해제하지 않으므로 기존 식별자로 신규 가입할 수 없습니다. 30일 삭제 정책을 운영에서 충족하려면 다음 단계를 먼저 완성해야 합니다. 기존 이메일 인증 문서·V1~V5·원본 ERD는 수정하지 않습니다.

### API

| Method | Path | 요청 | 성공 |
| --- | --- | --- | --- |
| POST | /api/v1/me/withdrawal | Bearer Access, Idempotency-Key(UUID), reauthProof, confirmed:true | 204, Refresh 쿠키 삭제 |

```json
{"reauthProof":"<WITHDRAWAL 목적의 재인증 증명>","confirmed":true}
```

EMAIL 회원은 기존 비밀번호 재인증 API, KAKAO 회원은 기존 동일 카카오 재인증·콜백·exchange에서 `WITHDRAWAL` 목적의 증명을 받습니다. 증명은 회원·현재 세션·목적에 묶이며 미소비·미무효화·5분 이내여야 합니다. `ADD_EMAIL_LOGIN` 등 다른 목적은 사용할 수 없습니다. 기존 Origin/CORS·HttpOnly/SameSite/Secure 정책을 유지합니다.

### 처리와 모듈 책임

`account-lifecycle`의 WithdrawalService가 모듈 contract를 조합합니다. member는 회원·프로필 이미지, identity는 계정·인증·세션·증명·OAuth 자료, terms는 동의 이력의 보관과 제거를 담당합니다. credit 데이터는 변경하지 않습니다.

한 READ_COMMITTED 트랜잭션에서 회원 행 잠금 → 멱등 결과 검사 → 현재 세션과 WITHDRAWAL 증명 잠금·소비 → 개인정보 스냅샷 암호화·저장 → 복구 식별자 예약 → 모든 세션·Refresh 폐기 → 인증 자료 무효화·평문 제거 → 동의·프로필 제거 → WITHDRAWN 전환을 수행합니다. 커밋 완료 후에만 204를 반환합니다. 암호화·저장·제거 중 실패하면 증명 소비까지 모두 롤백됩니다.

회원 잠금으로 같은 회원의 탈퇴·프로필 변경·재인증·연결을 직렬화합니다. 동일 회원·키·세션·증명으로 이미 인증을 통과한 동시 요청은 같은 완료 결과를 사용하며, 동일 키의 다른 요청은 409 IDEMPOTENCY_CONFLICT입니다. 커밋 후 재전송은 폐기된 JWT이므로 401입니다. 이를 우회하는 탈퇴 전용 인증 예외는 없습니다. 네트워크 응답 유실 시 프런트는 자동 로그인 성공으로 해석하면 안 됩니다.

JWT 경로의 기존 `SignupIdentityService.sessionActive()`는 이미 회원 ACTIVE를 확인합니다. 저장소의 세션 조회에도 ACTIVE JOIN을 추가했고, 세션 생성은 ACTIVE 회원 잠금 후에만 허용합니다. Refresh와 카카오 결과 교환, 기존 재인증·연결의 최종 쓰기도 비활성 회원·폐기 세션을 거부합니다. Refresh와 탈퇴가 경합해 먼저 발급된 토큰도 최종 탈퇴 커밋 후 사용할 수 없습니다.

### V6 DB 구조

| 구조 | 용도 |
| --- | --- |
| member 추가 필드 | withdrawal_generation, withdrawn_at, recoverable_until |
| withdrawal_operation | 회원·탈퇴 회차·요청키·세션·HMAC 지문·상태·보관 기한 |
| withdrawal_archive | 버전 1 암호문, 건별 데이터키의 래핑 암호문, 래핑 키 버전 |
| withdrawal_identity | EMAIL/KAKAO 목적별 HMAC 인덱스와 작업 참조, 중복 가입·연결 예약 |
| withdrawal_target | 외부 정리 대상의 암호화 위치·처리 상태·재시도·임대 필드. 워커는 후속 범위 |

member의 nickname/nickname_key/phone_number와 account의 email/email_key를 nullable로 변경합니다. 기존 UNIQUE는 유지되며 여러 탈퇴 회원은 NULL을 가질 수 있습니다. 기존 ACTIVE 회원 값은 마이그레이션에서 변경하지 않습니다. 작업은 member를 RESTRICT 참조하며 archive/identity/target은 작업 삭제에 종속됩니다. 기존 account·지갑·원장 FK는 그대로입니다.

스냅샷에는 기존 회원·프로필 이미지·계정·비밀번호 해시·카카오 연결·약관 동의를 포함합니다. 최상위 member/identity/consents 값은 각 모듈의 JSON byte[]를 base64로 저장한 값입니다. 하위 테이블 행은 DB 컬럼명을 소문자로 사용하고, 이진 값은 base64, 시각은 UTC 문자열입니다. 복구 구현은 형식 버전을 확인해야 하며 과거 status·탈퇴 회차를 그대로 덮어쓰면 안 됩니다.

활성 영역에서는 회원 이름·전화·프로필 참조·이미지·이메일을 제거하고 비밀번호 인증정보·카카오 연결·동의 행을 삭제합니다. 소유한 OAuth 컨텍스트·교환·흐름·멱등 응답은 제거하고, 증명·인증 요청의 대상 이메일·카카오 식별자를 지우며 메일 outbox를 취소·암호문 제거합니다. 과거 이메일 자료도 member_id 소유 관계로 처리합니다. 가입 전 병렬 흐름의 미사용 증명은 연결된 정확한 카카오 식별자로 소유 관계를 확보해 정리하며, 다른 식별자의 자료는 보존합니다. 세션·Refresh는 폐기 상태와 해시만 남깁니다. 지갑·원장은 그대로 유지합니다.

HMAC 인덱스도 개인정보에 해당하는 보관 자료이며 후속 삭제 대상입니다. signup/account 생성, 이메일 변경, 카카오 연결의 최종 저장 경계에서 예약을 재검사하며 동일 식별자 예약 잠금을 사용합니다. 탈퇴 회원의 카카오 OAuth는 현재 401로 차단합니다. 향후에는 본인 확인 후 복구 전용 결과로 분기해야 합니다.

### 암호화와 인프라 한계

탈퇴 건마다 새 AES-256 데이터키와 GCM nonce를 생성합니다. operation ID·버전으로 AAD를 결합해 암호문·키의 다른 작업 간 교환과 변조를 거부합니다. 데이터키는 기존 AUTH 암호화 키로 래핑하며 기존 키를 재생성하지 않습니다. 애플리케이션은 키·스냅샷·증명 원문을 로그나 응답에 출력하지 않습니다. JSON 암호화에 사용한 주요 byte[]와 원시 데이터키는 처리 후 덮어쓰지만, JVM·직렬화 과정의 모든 메모리 사본 제거를 보장하는 것은 아닙니다.

현재 wrapping_key_id는 `auth-encryption-v1`이며 운영 키 교체·키 버전 레지스트리는 후속 과제입니다. DB/백업에 래핑된 키와 암호문이 있고 기존 AUTH 키에 접근할 수 있다면 복호화할 수 있습니다. 따라서 DB 행 삭제만으로 백업·바이너리 로그·스냅샷의 암호학적 삭제를 보장하지 않습니다. 별도 키 저장소·건별 키 폐기·백업 보존/복원 후 삭제 재적용 정책이 필요합니다. 법적·회계상 보존 자료의 범위는 미확정이며 영구 보존 로직은 추가하지 않았습니다.

현재 프로필 이미지는 DB BLOB이므로 암호화 보관과 원문 제거가 같은 트랜잭션에 포함됩니다. 외부 객체 저장소는 연결되어 있지 않아 외부 삭제 작업을 생성하지 않습니다. 이미 SMTP 제공자에게 전송 중인 메일은 회수할 수 없으며, 이후 저장·재시도는 취소와 임대 검증으로 차단합니다.

### 검증과 다음 단계

2026-11-16 최종 `gradlew test` 실행은 전체 780건, 실패·오류·건너뜀 0건입니다. 이 중 MySQL Testcontainers는 383건이며, 탈퇴 테스트 클래스는 H2/MySQL 각각 99건(기존 인증 회귀 포함), 별도 MySQL V5→V6 업그레이드 검증은 1건입니다. 세부 보고서는 `build/reports/tests/test/index.html`, 실행 로그는 Git 제외된 `build/withdrawal-final-tests.log`입니다.

WithdrawalTests와 MySqlWithdrawalTests는 별도 회원으로 EMAIL/KAKAO 탈퇴, 전체 세션 폐기, 개인정보 제거·아카이브 복호화, 기존 지갑·보상 유지, 증명의 목적·회원·세션·만료, 확인·Origin 검증, 중복·동시 요청, Refresh 경합, 암호화/저장/제거 실패 롤백을 검증합니다. MySqlWithdrawalMigrationTests는 V5 기존 계정에서 V6 업그레이드 시 값이 보존되는지 확인합니다. 외부 카카오·SMTP 네트워크는 테스트 대역을 사용하며 실제 사용자 계정을 탈퇴시키지 않습니다.

후속 범위는 실제 이메일 확인 후 새 비밀번호를 설정하는 복구, 동일 카카오 식별자 기반 복구, 복구 시 최신 약관 처리, 닉네임 재사용 충돌 정책, 새 세션 발급, 만료 직전/정각 경계 검증, FK 순서에 따른 삭제와 예약 해제, 외부 정리 워커·백업·키 폐기입니다. 복구 시 회원·지갑 생성이나 가입 보상 지급 함수를 호출해서는 안 됩니다.
